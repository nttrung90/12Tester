# Review notes for implementation follow-up

These notes reflect the first implementation in progress. Recheck against final source before changing anything.

1. PrefetchedCandidates currently caches for the entire business day without mutation stamp or bounded age. Before the change, dismissing cleared the single next choice and reopening fetched again. Retaining the candidate list all day can continue suggesting campaigns that have since filled/paused/been tested, even after local report or campaign invalidation. Match repository campaign mutation version; clear/reload after invalidation, dismiss/new submission lifecycle, or use the existing candidate freshness boundary without enlarging TTL. Do not introduce polling or unconditional double requests. A same-day matching identity is insufficient freshness.
2. consumePrefetchedCandidates launches independent viewModelScope jobs without a sequence/cancel guard. An older consumer can overwrite a retry/newer consumer or repopulate UI after dismiss. Check request identity at every suspension boundary and publication, both success and failure. New fetch should clear old nextCampaignToTest so the old Test button cannot win over loading/error. Handle identity/day changes without leaving loading forever; don't label stale discarded results as successful emptiness.
3. In v2 missing-stats batch repair, newly fetched stat.hasTestedToday must exclude the campaign if the tester submitted since the candidate fetch. Validate all final candidates have a campaign ID, current-day count and date. On legacy path, don't turn missing statsDate into today's date or quietly skip missing stats and report all-done: repair or return a load error where no reliable eligibility/target data exists. Account for existing CampaignStats count defaults when defining missing-data handling.
4. NextCampaignSelector.isTargetMet currently uses todayTestedCount ?: 0. This contradicts the requirement not to assume missing count means zero. Ensure invalid/unknown counts cannot enter group 1/2, e.g. reject incomplete input explicitly and test it; also reject negative counts from malformed payloads.
5. Preserve first-ever submission selection when consuming prefetch after worker DONE, and when prefetch is still running at submit. Snapshot the first-submission preference for the actual request; don't recompute from testedInThisViewModel after completion or cancel/restart the initial prefetch and lose the original state. An old firstTimeTester captured for another identity must not classify a new user's session.
6. Add meaningful ViewModel/repository behavioral tests for these races and malformed/old payloads; pure selector tests and string assertions alone do not verify prefetch safety. Full-app submission/reward should also be verified through real local SQL calls after applying new migration, not just inserting checkins or reading source.
