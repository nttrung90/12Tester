# Independent review findings, round 1

These findings are against the initial 078 migration. Do not edit the independent reviewer test or weaken existing tests.

1. **P1 — owner resume threshold regressed to constant 3.** In 078's replacement `resume_campaign`, `v_threshold integer := 3` never reads `owner_auto_pause_configs`. Migration 075 reads the configured missed_days with fallback 7. Restore that behavior exactly while adding the reason clearing. Reproduction: `node audit/admin-pause-reason-popup-2026-11-05/review-regression.mjs`, final group: threshold 7, controlled streak 4, owner_manual pause must reopen; currently raises OWNER_INACTIVE. Also cover threshold 1 with streak 1, which must be rejected. Existing owner-auto-pause tests pass because their later resume cases leave config at 3; this is a real gap, not proof of compatibility.

2. **P2 — admin resume result contract lost fields.** Original `_impl_admin_resume_campaign` in 069 returns `paused_reason: null` and `admin_resumed: v_hold_open` on successful reopening. 078 omits both. Restore those fields; otherwise callers decoding AdminCampaignControlResult silently get default adminResumed=false when resuming owner_inactive should return true. Keep the existing completed branch contract.

3. **P2 — audit reason changed outside scope.** Original 073 admin_resume_campaign records `Khôi phục chiến dịch bởi Admin` as its reason. Replacement 078 writes null. Restore the original audit reason while retaining improved row locking and expanded snapshot.

4. **P2 — lifecycle normalization misses the new code.** The existing `trg_campaign_status_lifecycle` clears paused_reason and admin_note when trusted code reopens an app via UPDATE status='open'. 078 does not extend it to clear admin_pause_reason_code, so trusted lifecycle writes can leave an open app carrying a stale policy code. Add the new field to the existing open-branch normalization while preserving completion behavior. Independent review-regression.mjs now covers this invariant in a rolled-back transaction; keep the existing RPC checks as well.

5. **P1 — new dialog cleanup does not isolate Admin A from Admin B.** Current Screen LaunchedEffect(currentUserId,isAdmin) clears only when !isAdmin or currentUserId==null. Switching between two authenticated admins never satisfies that condition, so the dialog/draft can remain. In addition, the new currentUserId is set from effectiveUserId(), which returns the constructor's frozen myUserId when non-null; it is not updated immediately on auth changes/logout and lacks session generation. Use a live, observable session identity (UID + generation), update it before network refresh, and clear dialog/selected reason/custom draft whenever that identity changes, including admin-to-admin and logout/relogin with the same UID. Preserve ordinary network-failure drafts within the same session. Add behavioral tests for both boundary cases and for a late response from the old session; do not merely test the existing helper token paths.

6. **Check missing-backend feedback before acceptance.** Plan requires an explicit backend-not-updated error for absent new RPC, no silent legacy fallback. Current generic adminCampaignActionError has no such mapping. New modal stays open on failure, while the old error snackbar is on the underlying screen, so ensure the Admin can see the failure message in the modal and retry without losing the draft. Add a PGRST202/404 fixture asserting a single new RPC request, zero legacy fallback, clear actionable error and no success callback.
