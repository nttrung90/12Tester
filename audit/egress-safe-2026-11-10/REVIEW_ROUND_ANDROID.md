# Review Android đang triển khai

Các phát hiện này dựa trên bản đang viết; đối chiếu lại trước khi sửa. Chưa coi implementation là hoàn tất chỉ vì compile/test đang có qua.

1. **Token và payload đang tách rời, token được ghi trước race fence.** `homeFeedTokens`, `dashboardTokens`, `detailTokensCache` cập nhật ngay khi response về, còn payload chỉ ghi sau kiểm tra generation/mutation. Response cũ có thể làm bẩn token mới sau invalidation hoặc đổi tài khoản. Detail token còn khóa bằng campaignId trong khi payload khóa campaignId|uid. Phải dùng snapshot bất biến gồm scope + token + payload và publish nguyên tử dưới cùng fence; token không bao giờ sống độc lập với giá trị tương ứng.

2. **Đọc prev sau await.** Request gửi token của bản A nhưng lấy prev mới nhất sau response thay vì đúng snapshot A đã gửi. Khi mutation/concurrent refresh xen giữa, changed=false có thể ghép sai nội dung. Chụp một snapshot nguyên tử trước request, merge đúng snapshot đó, không merge vào state đọc sau mạng; commit được bảo vệ race fence.

3. **Thiếu validation bắt buộc/schema/ngày/value presence.** `SyncBlock.value: T?=null`, `changed=true` mặc định, `schemaVersion=2` mặc định, businessDate rỗng mặc định và nhiều block optional làm response thiếu được hiểu thành thành công. `?: emptyList()/0/false` che dữ liệu lỗi. Cần raw JSON envelope validation: schema/day phải xuất hiện, changed phải Boolean, token hợp lệ, đầy đủ key bắt buộc; changed=true phải có key value kể cả JSON null hợp lệ. Null chỉ được phép ở field nullable. changed=false cần đúng base value còn giữ. Bất kỳ lỗi protocol phải repair full tối đa một lần và không publish/cache partial.

4. **Repair thiếu.** Feed chỉ kiểm tra open/stats, không paused/completed/owner_names. Dashboard và detail chưa có repair đầy đủ. Response repair phải được kiểm tra lại như initial full. Không fallback legacy sau sync thành công nhưng merge thiếu vì có thể lặp side effect; bounded repair có chủ đích, nếu vẫn hỏng thì lỗi rõ ràng giữ UI cũ.

5. **Cờ mặc định true, rollback mới là biến RAM.** Plan yêu cầu legacy mặc định và vận hành bật/tắt được thực tế. Cần nguồn cấu hình thực (tận dụng app_configs với các boolean additive default false, áp dụng khi config được tải/restored; hoặc cơ chế khác có consumer thật, không thêm round trip chặn UI). Bật/tắt từng endpoint, reset metadata phù hợp. Không tuyên bố remote rollback nếu chỉ có setter không được gọi.

6. **Telemetry hiện không đo byte và gán sai trigger.** Đừng gán mọi forceRefresh thành PULL_REFRESH; nhiều forceRefresh do mutation/prefetch. isCacheHit không đúng khi chỉ hai block không đổi nhưng khối khác đổi. Tách cache hit local, single flight, network request, network unchanged; byte wire nếu không đo được phải nullable/unknown, không dựng 0 hay lấy decoded làm wire. Đọc body thực tế một lần và đo decoded UTF8. Có đường dùng/kiểm thử trigger source và counters.

7. **Missing-RPC classifier hiện legacy rộng.** Xác minh code PGRST202 + đúng tên hàm/signature cần tìm; không dùng matching chuỗi bất kỳ như 'not found' cho v2 fallback. Lỗi 401/403/5xx/timeout/deserialization không đánh dấu missing. Capability cache phải scope backend/client, đồng hồ test được, hết hạn và cờ toggle kích hoạt lại được.

8. **Cần behavioral tests qua repository thật với MockEngine.** Existing `AdminRelatedRepositoryRaceTest.kt` có mẫu createSupabaseClient + Auth MemorySessionManager + Ktor MockEngine + Robolectric. Test cold/full/partial/unchanged/empty/null, token-only/partial malformed full repair count, missing RPC fallback count + expiry, forbidden errors, ngày chuyển, evict token/value, mutation và user switch response cũ về sau. Kiểm tra request p_tokens chính xác và false serialize. Không chấp nhận chỉ test merge helper hoặc đọc chuỗi source thay cho integration pipeline.

9. **B1/Profile phải giữ hai trigger.** Kiểm tra single flight không gộp qua ngày/mutation; hợp nhất callback Profile khi đồng thời, giữ resume và mở tab. Không đổi TTL hoặc debounce gây chờ. DataStore/snapshot chỉ có token khi có full payload cùng scope; nếu chưa persist token thì bỏ token khi process death là an toàn nhưng cần nêu giới hạn tiết kiệm cold start.

10. **Independent DB checks đã có bằng chứng thật.** `audit/egress-safe-2026-11-10/runs/verify-egress-edge-cases.mjs` đã qua: 205 reports + window200 + pending ngoài window, 3 attachments, giữ credentials/full fields, scope tester/outsider với owner tokens, profile đổi từ xa, 15 candidates đúng thứ tự, anon denied dashboard/detail. Log ở `runs/independent-db-review.log`. Các comment '200 reports/attachments' trong test mới của Gemini trước đó chưa tự tạo fixture tương ứng; không claim những test đó nếu không thật sự chạy. Đo JSON dashboard fixture full=6770, unchanged=1699; đây là decoded fixture, không phải production egress.
