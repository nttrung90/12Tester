# Kế hoạch sửa lỗi luồng tương tác chủ app ↔ người test (chỉ client)

## Các lỗi sẽ sửa

- **B1** `data/ReportSubmitManager.kt:303` — luôn phát `SubmitEvent.Success`, guard chỉ áp cho state (sự kiện thưởng bị nuốt khi nộp 2 app liên tiếp).
- **B2** `CampaignDetailScreen.kt:155` + `CampaignDetailViewModel` — `effectiveUserId()` thay cho `myUserId` đóng băng khi session đang khôi phục.
- **B3** `CampaignRepository.getCampaignReports` — RPC thành công (kể cả rỗng) → cache + trả về; RPC lỗi → fallback; cả hai lỗi → ném lỗi, không cache rỗng 3 phút.
- **B4** `CampaignRepository.kt:893` — `totalReportsCount = reports.size` (bỏ `coerceAtLeast(checkins.size)`).
- **B5** `OwnerAppDetailViewModel` — fallback profile chủ app chỉ khi `ownerId == myUserId`; màn hình hiển thị placeholder khi null.
- **B6** `CampaignRepository` — `updateCampaignStatus/Details/Icon` chuyển sang update cột mục tiêu, bỏ upsert full-row.
- **B7** `DailyTaskCard.kt` — fallback % phạt 1/2/5/10 khớp server.
- **B8** `OwnerAppDetailScreen` chip trạng thái — dùng helper model, status lạ hiển thị nhãn trung tính (+ strings 3 ngôn ngữ).
- **B9** Hằng số `PROVISIONAL_CREDITS = 10` thay hard-code trong thông báo dự phòng.
- **B10** Bỏ rollback snapshot optimistic trong approve/reject; lỗi → error message + refresh().
